Deployment

EngineersIT leadership
In short

The app runs in Microsoft Azure as one container that both collects and serves the website, with its data on a file share that survives restarts. Updates roll out without taking the site down. A second computer can stand by to collect if the main collector ever stops, and the app checks its own health and security every day.

Three standard notations describe the work around the product: BPMN for the routine outage process, CMMN for investigations (which don't follow a fixed path), and DMN for decisions (chapter 4.4). A Six Sigma view shows how the product supports continuous improvement.

7.2 Investigations as a case (CMMN view)

An investigation is knowledge work: people decide what to do next. CMMN models it as a case file with stages, entry criteria (sentries) and milestones, rather than a fixed sequence.

CMMN elementIn the product
Case fileThe investigation record: title, station, category, impact, assignee, root cause, actions, ITSM and Wepa case numbers, linked outages, notes
Stage: AnalyzeEntry sentry: an assignee is set (also sets the escalation date)
Stage: RespondEntry sentry: a root cause, marked suspected or confirmed
Stage: ReviewEntry sentry: the action taken is recorded. Exit needs a different person (separation of duties)
MilestonesClosed Complete; Closed Incomplete; Closed Cancelled (each needs a written reason)
Discretionary tasksAdd a note; link outages; download the evidence packet; override impact
Event listenerThe detector opens a case when a printer has 3 or more unreachable or hardware outages in 14 days
Case file integrityEvery change is an event with the previous event's SHA-256 hash; archived 2 years after closing
